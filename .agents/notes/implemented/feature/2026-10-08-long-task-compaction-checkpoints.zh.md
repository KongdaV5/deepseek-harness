# Agent Note: 通过压缩检查点续接长任务

Status: implemented

[English](2026-10-08-long-task-compaction-checkpoints.md) | 中文

## Problem

长时间编码轮次可能在输出达到上限前多次压缩对话历史。现有任务进度提示覆盖已完成阶段和输出受限后的续跑，但没有明确要求在上下文压缩前保存检查点、记录已查看的源码区间，也没有要求模型在压缩摘要后从未完成处继续且避免重复查看未变化的代码。

## Decision

启用有界任务续跑后，系统提示会要求模型在大范围查看代码前创建或复用一份简洁的工作区检查点。每个发现阶段结束时，记录重要路径和已查看的准确行区间，并区分只读检查与实际修改。在预计上下文压缩或输出达到上限前更新检查点。出现压缩摘要或自动续跑后，读取并核对检查点，从第一个未完成阶段继续；除非源码已变化或缺少必要证据，否则不重复读取已查看的区间。

## Alternatives considered

**由宿主拦截重复文件读取。** 不采纳，因为文件变化后可能需要重新读取，或先前输出未包含所需证据；仅匹配路径和区间无法证明后续读取是多余的。

**禁用或延迟上下文压缩。** 不采纳，因为此检查点改动不改变模型上下文容量，也不改变长会话保持在该容量内所需的压缩策略。

## Consequences

后续压缩轮次可从检查点恢复任务阶段与已完成的检查。这属于模型指引，而非宿主强制的读取去重，因此无法保证模型一定写入检查点或绝不重复读取。它不会降低压缩请求的延迟或 token 成本。
